# Настройка Firebase для сайта «Скурим»

Сайт работает и без Firebase (локально, как и раньше — данные только в
твоём браузере). Ниже — как включить облако: аккаунты игроков и
синхронизацию сессий в реальном времени.

## 1. Создать проект

1. Зайди на https://console.firebase.google.com
2. «Добавить проект» → название любое (например `skurim-ttrpg`) → без
   Google Analytics можно (не нужен) → «Создать проект».

## 2. Включить Authentication

1. В меню слева: **Build → Authentication** → «Начать работу» (Get started).
2. Вкладка **Sign-in method** → включи **Email/Password** (просто
   переключатель в положение «включено», сохранить).
3. Там же включи **Google** → выбери email для поддержки проекта → сохранить.
4. Вкладка **Settings → Authorized domains** — добавь домен своего сайта
   на GitHub Pages (например `pumpampim.github.io`). Без этого шага кнопка
   «Войти через Google» будет выдавать ошибку — `localhost` и
   `*.firebaseapp.com` там уже есть по умолчанию, а твой домен нужно
   добавить руками.

## 3. Включить Firestore Database

1. В меню слева: **Build → Firestore Database** → «Создать базу данных».
2. Режим: **Начать в тестовом режиме** (production-правила мы всё равно
   заменим своими на шаге 5) → выбери ближайший регион → «Готово».

## 4. Зарегистрировать веб-приложение и получить конфиг

1. На главной странице проекта нажми значок `</>` («Добавить приложение» →
   Web).
2. Название приложения — любое (например `skurim-web`). Галку
   «Firebase Hosting» можно не ставить — мы используем GitHub Pages.
3. Появится блок кода с `const firebaseConfig = { ... }` — скопируй его
   целиком.
4. Открой файл **`firebase-config.js`** в репозитории и вставь
   скопированные значения вместо `"ВСТАВЬ_СЮДА..."`.

## 5. Настроить правила безопасности Firestore

1. **Build → Firestore Database → Rules** (вкладка «Правила»).
2. Полностью замени содержимое на текст из файла **`firestore.rules`**
   (он лежит рядом, в репозитории) → «Опубликовать» (Publish).

   Эти правила рассчитаны на закрытую группу друзей: любой, кто вошёл в
   аккаунт, может участвовать в сессиях, но не может редактировать чужой
   постоянный лист персонажа.

## 6. Залить файлы на GitHub

Так же, как раньше — `firebase-config.js` можно спокойно коммитить в
публичный репозиторий: `apiKey` в Firebase — это не секрет (в отличие от
паролей), доступ реально ограничивают правила из шага 5.

После пуша просто открой свою страницу на GitHub Pages — сайт сам
подхватит настроенный Firebase (в верхней строке статуса вместо
«Офлайн-режим» появится окно входа).

## 7. Проверка

1. Открой `index.html` на сайте → должно появиться окно входа →
   зарегистрируй тестовый аккаунт.
2. Открой `gm.html` → войди тем же (или другим) аккаунтом → «Создать
   новую сессию» → получишь код.
3. На `index.html` во вкладке «Сессия» введи этот код → «Присоединиться».
4. Измени HP на своём листе — на `gm.html` в «Отряде» число должно
   обновиться за секунду-две без перезагрузки страницы.
5. В блоке «📦 База предметов» на `gm.html` нажми «Импорт» один раз —
   он загрузит все 437 предметов из `items-data.js` в Firestore.
   Повторный клик безопасен — обновит те же записи, а не создаст дубли.

## Известные упрощения (MVP)

- Правила Firestore для сессий сознательно простые (любой авторизованный
  участник может писать в сессию) — этого достаточно для доверенной
  группы друзей, но не годится для публичного сервиса.
- Кастомные заклинания (`customSpells`) пока сохраняются только локально
  (`localStorage`), в облако не уходят — при желании допишем отдельно.
- Если несколько человек одновременно правят одного и того же
  противника или показатели одного игрока — побеждает последняя запись
  (никакого разрешения конфликтов нет). Для боевых заметок это не
  критично.
